# Snap2Store — 찍으면, 등록까지

**팔 물건을 사진 찍어 올리면, 자율 에이전트가 네이버 스마트스토어 등록을 끝까지 수행한다.**
사람은 첫 입력 이후 아무것도 하지 않는다.

> 실제 등록된 상품 URL: _(첫 실등록 후 여기에 붙인다 — 아직 실행하지 않았다면 비워 둔다.
> 이 줄에 만들어 낸 링크를 넣지 않는다.)_

---

## 왜 어려운 일인가

스마트스토어 상품 하나를 살리려면 이 열 칸이 전부 채워져야 한다.

```
대표 이미지 · 추가 컷 · 상품명 · 카테고리 · 판매가
상세페이지 · 검색 태그 · 원산지 · KC 인증 · 상품정보제공고시
```

각 칸은 서로 의존한다. 카테고리가 정해져야 고시 유형과 KC 대상 여부가 나오고, 상품 정체가
확정돼야 카테고리를 찾을 수 있고, 시장 어휘를 알아야 검색되는 상품명을 쓸 수 있다.
개인 판매자는 이 의존 그래프 때문에 등록을 포기한다. 그 그래프를 사람 대신 밟는 것이 이
에이전트의 일이다.

## 포지셔닝 — 얇은 에이전트 루프 + 두꺼운 실도구

도구 호출의 결정(순서·횟수·생략)은 매 입력마다 모델이 한다. 실행은 검증된 실재료
파이프라인(실제 커머스 API, 실제 카탈로그 투표, 실제 등록 POST)이 한다.
실행이 끝나면 **진짜 상품 번호와 진짜 스토어 URL**이 나온다.

## 실행

```bash
npm install
cp .env.example .env.local          # 키를 채운다
cp config/smartstore.example.json config/smartstore.local.json
npm run dev:full                    # API :8788 + UI :5173
```

| 화면 | 주소 |
|---|---|
| 제품 화면 | http://localhost:5173 |
| 세컨드 화면 (raw API 스트림) | http://localhost:5173/stream |
| 폰 카메라 (QR 로 진입) | https://\<맥 LAN IP\>:8443/phone?s=코드 — 랜딩의 "핸드폰으로 찍기"가 QR 을 만들어 준다 |

### 환경변수 (`.env.local`)

| 키 | 필수 | 용도 |
|---|---|---|
| `OPENAI_API_KEY` | ✅ | 에이전트 루프 · 구조화 JSON · 이미지 생성 |
| `OPENAI_MODEL` | | 기본 `gpt-5.6-luna`. 지연이 전부다 — 같은 세대에서 더 빠른 변종이 있으면 교체 |
| `OPENAI_IMAGE_MODEL` | | 기본 `gpt-image-2` |
| `NAVER_COMMERCE_CLIENT_ID` / `_SECRET` | ✅(실등록) | 카테고리·고시·KC·원산지·태그·카탈로그·등록 |
| `COMMERCE_PROXY_URL` | ✅(실등록) | 커머스 API IP 화이트리스트 대응 고정 IP 프록시 |
| `NAVER_SEARCHAD_*` | | 상품명·태그 검색 수요 검증 (선택) |
| `SMARTSTORE_MODE` | | 기본 `live`. `dry-run` 은 사람이 고르는 모드가 아니라 시스템이 스스로 내려앉는 바닥 |
| `LINK_HTTPS_PORT` | | 기본 `8443`. 폰 카메라용 HTTPS 포트 — 자체 서명 인증서를 `data/cache/link-tls/` 에 자동 생성 |
| `LINK_TUNNEL` | | 기본 `off`. `auto` 면 부팅 때 cloudflared 인터넷 터널을 미리 연다 (와이파이 제약·인증서 경고 제거) |
| `VOICE_REALTIME_MODEL` | | 기본 `gpt-realtime-2.1`. 음성 서기 1홉 경로 — 발화를 직접 이해해 메모를 쓴다 |
| `VOICE_TRANSCRIBE_MODEL` | | 기본 `gpt-4o-transcribe`. 자막(입력 전사) 사이드카 + 폴백 전사 모델 |
| `VOICE_SCRIBE_MODEL` | | 폴백 2홉의 메모 정리 텍스트 모델. 비우면 `OPENAI_MODEL` |
| `VOICE_LANGUAGE` | | 기본 `ko` |

> ⚠ `.env.local` 이 진실의 원천이다. 셸 프로필에 낡은 `OPENAI_API_KEY` 가 export 돼 있으면
> `echo $OPENAI_API_KEY` 로 확인해 지운다 — 파일 값이 조용히 지는 사고가 난다.

## 아키텍처

```
사진 업로드 (POST /api/listings)
    │
    ├──────────────► 이미지 스위트 프리워밍 (즉시 시작, 에이전트와 완전히 겹침)
    │                 gpt-image-2 · 업로드한 사진 **전부**를 참조로 (최대 16장)
    │                 대표 컷을 먼저 만들고, 그 결과를 나머지 샷의 정체성 앵커로 재사용
    │                 (거부 판정이 나면 AbortSignal 로 즉시 취소된다)
    │
    └──► 에이전트 루프 (Agents SDK, 스트리밍)
           │  도구 호출의 개수·순서·생략을 모델이 결정한다
           │  ├ resolve_category      (카탈로그 투표 → leaf 매핑 → LLM 검증 루프)
           │  ├ research_market_price (comps 분포 or 에이전트 추정)
           │  ├ generate_image_suite  (논블로킹 진행 스냅샷)
           │  └ web_search (hosted)   (브랜드 인쇄·주장 시 의무 1회)
           │
           └──► 구조화 draft (zod 검증)
                  │
                  ├─ [거부 게이트] riskLevel === "high" → 즉시 종착 (재료 생산 앞)
                  │
                  └──► 오케스트레이터: 재료 병렬 생산
                         ├ 카테고리 (도구 결과 재사용, 없으면 서버 폴백)
                         ├ ┌ 상품명 SEO → 태그 포트폴리오 (순서 의존 체인)
                         │ ├ 고시 · KC · 원산지 · 가격 · 상품속성
                         │ └ 상세 기획 → 세로 패널 생성
                         │   (위 세 갈래가 Promise.all 로 동시)
                         │
                         └──► 검증 · 폴백 해소 → 이미지 업로드 → 상세 HTML 조립
                                → 프리플라이트 → 등록 POST (무재시도)
```

**병렬화가 지연 예산의 전부다.** 직렬로 짜면 어떤 최적화도 90초를 못 맞춘다.

## 자율성 계약

첫 입력 이후 사람의 버튼·추가입력·수동실행이 **0회**로 종착지에 도달한다.
게이트 위반은 사람에게 넘기지 않고 폴백으로 자가 해소한다.

### 폴백 4종

| # | 게이트 위반 | 자가 해소 |
|---|---|---|
| 1 | 상품명이 등록 게이트를 어김 | `repairTitle` 로 자동 보정 → 재게이트. 재통과 실패해도 경고만 남기고 진행 |
| 2 | 카테고리 검증 루프 미통과 | 득표 1위 후보 자동 채택 + "미검증" 라벨 |
| 3 | 원산지 미판독 | 판매자 설정 기본값으로 진행 (허위가 아니라 설정 사실) |
| 4 | 시세·추정 모두 부재 | 설정 최저 안전가로 진행 + "검토 권장" 라벨 |

### 자동 강등

실등록이 물리적으로 불가능한 사유(카테고리 미확정, 프리플라이트 실패, 이미지 업로드 실패)는
**쓰기만 강등**하고 등록안은 끝까지 완성해 보고한다. 화면은 모드가 아니라 결과를 말한다 —
"등록안 완성 — 스토어 전송 보류".

### 유일한 중단

**고위험 거부 판정 하나**다. `riskLevel: "high"` 는 입력 대기가 아니라 판단이 담긴 최종
산출물이며, 재료·이미지 생산 **앞**에서 실행된다.

## 폰 링크 — 핸드폰이 카메라가 된다

랜딩의 **"핸드폰으로 찍기"** 를 누르거나, **카메라 앞에 핸드폰을 들어 보이면**
([폰 아이](#폰-아이--들어-보이면-열린다)) QR 이 뜬다. 폰 카메라로 스캔하면:

1. 웹에 **스튜디오 모니터가 켜지고** 폰 카메라 라이브 뷰가 거의 전체 화면으로 흐른다
2. 폰에서 셔터를 누르면 웹에서 플래시 → 프리즈 프레임이 필름 스트립으로 날아가 앉고,
   **원본 화질 사진이 업로드 트레이에 그대로 담긴다**
3. 연결돼 있는 동안의 발화는 **받아쓰기가 아니라 서기**다 — `gpt-realtime-2.1` 이 소리를
   직접 이해해(텍스트 출력 전용 세션) 잡담을 버리고 정정을 반영한 **메모 전문**을 매 발화마다
   다시 쓴다. 원문은 자막으로 흐르고, 정리본이 "덧붙일 정보" 칸을 채운다.
   realtime 모델이 조직에 안 열려 있으면 전사(`gpt-4o-transcribe`) + 텍스트 모델 정리의
   2홉으로 **자동 폴백**한다
4. 폰 또는 웹에서 "촬영 마치기" → 모니터가 꺼지고, 트레이에 담긴 사진으로 바로 등록을 시작한다

전송은 WebRTC 가 아니라 **서버 경유 WebSocket 릴레이**다 — 시연장 와이파이의 P2P 차단(클라이언트
격리)에도 "폰이 페이지를 열 수 있으면 스트림도 된다"는 단일 조건으로 좁혀진다. 폰 페이지는
`/stream` 과 같은 원칙으로 **빌드 없이 Express 가 직접 서빙**한다 — 프론트 빌드가 깨져도 산다.

### 폰 아이 — 들어 보이면 열린다

QR 을 부르는 데 클릭이 꼭 필요하진 않다. 랜딩이 떠 있는 동안 **맥북 내장 카메라**가
화면 앞을 지켜보다가, 사용자가 **핸드폰을 들어 보이면 스스로 QR 을 연다**. 버튼을
누르는 한 동작이 "보여주기"로 바뀐다.

- 모델은 브라우저 안에서 도는 **MediaPipe `ObjectDetector` (EfficientDet-Lite0, COCO)**
  다. 프레임도 추론도 기기 밖으로 나가지 않는다 — 서버로 보내는 건 아무것도 없다.
- **wasm·모델 전부 우리 오리진에서 나간다.** wasm 은 `npm run dev`·`build` 직전
  `scripts/vendor-vision.mjs` 가 `node_modules` 에서 복사하고, 모델은 저장소에 들어 있다.
  시연장 네트워크에 추론을 거는 경로가 없다 (폰트를 로컬로 받는 것과 같은 이유).
- 판정은 **클래스 + 점수 + 면적 + 지속**이다. 점수만 보면 *책상에 놓인 폰* 때문에
  페이지를 열자마자 QR 이 튀어나온다. 그래서 **가까이(프레임의 3% 이상), 0.6초 이상**
  버텨야 의도로 인정한다. CTA 아래 게이지가 그 확신이 차오르는 걸 보여준다 —
  QR 이 난데없이 튀어나오면 마법이 아니라 오작동으로 읽힌다.
- **울리면 카메라를 끄고, 폰을 내렸다 들어야 다시 무장한다.** QR 을 닫는 순간 손에 든
  그 폰이 QR 을 다시 여는 루프를 막는다. 랜딩이 맨 앞에 있고 아직 폰이 안 붙었을 때가
  아니면 눈은 아예 감겨 있다.
- **버튼을 대체하지 않는다.** 카메라가 없든 권한이 거부되든 모델이 안 뜨든
  "핸드폰으로 찍기" 버튼은 그대로 산다. 마법이 실패했을 때 돌아갈 자리가 있어야 한다.

기준선 튜닝은 실험실에서 한다 — `http://localhost:5173/?eye=1` 에서 실시간 박스·점수·
면적·**탈락 사유**를 보며 슬라이더로 문턱을 흔들 수 있다. 재현율이 모자라면 더 무거운
모델로 비교한다 (`npm run vision:lite2` 로 받은 뒤 실험실에서 전환 — 저장소에는 넣지 않는다).
**심사·시연 경로가 아니다. 튜닝 전용이다.**

### 준비물 · 트러블슈팅

- **연결이 안 되면 답은 "인터넷 터널 켜기"다.** QR 모달의 버튼 하나로 cloudflared 퀵 터널
  (`https://*.trycloudflare.com`)이 열리고 QR 이 그 주소로 바뀐다 — **폰이 LTE 든 다른
  와이파이든 접속되고, 정식 인증서라 "비공개 연결" 경고도 없다.** 준비물은
  `brew install cloudflared` 하나. `LINK_TUNNEL=auto` 면 부팅 때 미리 데워 둔다.
  (프레임이 CF 엣지를 돌아오므로 지연은 LAN 직결보다 늘어난다 — 기본은 여전히 LAN.)
- LAN 모드일 때: 폰과 맥이 **같은 와이파이**에 있어야 한다 — **LTE/5G 데이터로는 절대
  열리지 않는다** ("찾을 수 없는 페이지"의 제1 원인). 같은 와이파이인데도 안 되면
  공유기의 기기 간 통신 차단(AP 격리)이다 → 터널을 켜거나, **폰 핫스팟에 맥을 연결** →
  **"주소 새로고침"** → 새 QR 스캔.
- QR 이 번거로우면 폰 브라우저에 모달이 알려주는 짧은 주소(`<맥 IP>:8788/p`)를 직접 치면
  된다 — https 폰 페이지로 넘어가며, 거기서 **세션 코드 6자리를 입력**해 입장한다.
- 첫 접속 때 자체 서명 인증서 경고가 한 번 뜬다 — **"세부사항 → 계속(방문)"** 으로 통과한다.
  카메라(getUserMedia)는 HTTPS 필수라 생기는 비용이고, **시연 전에 미리 한 번 통과시켜 둔다.**
- 18초 넘게 폰이 안 붙으면 QR 모달이 스스로 원인 점검 가이드를 펼친다.
- 폰 없이 흐름을 리허설하려면 데스크톱 브라우저에서
  `http://localhost:5173/phone?s=<세션코드>&sim=1` — 가짜 카메라(움직이는 캔버스)로 전 구간이 돈다.
- 음성 서기는 `OPENAI_API_KEY` 가 있으면 자동으로 켜진다. 없으면 조용히 꺼지고
  카메라·셔터는 그대로 동작한다.

## 세컨드 화면 — `/stream`

`tool_call` **과** `tool_result` 가 가공 없이 실시간으로 흐른다. 빌드 파이프라인에 넣지
않고 Express 가 문자열 상수로 직접 응답하므로, 프론트 빌드가 깨져도 살아 있다.

| 채널 | 무엇이 흐르나 | 색 |
|---|---|---|
| `tool_call` | SDK 가 방출한 도구 호출 원본만 | 앰버 |
| `tool_result` | SDK 가 방출한 도구 결과 원본만 | 그린 |
| `openai_raw` | 모델 raw 스트림 이벤트 전량 | 블루 |
| `image` | 이미지 샷 시작/완료 | 마젠타 |
| `milestone` | **서버 파이프라인 진행 보고** (도구 결과가 아님) | 시안 |
| `status` | 스테이지 전환 | 회색 |
| `error` | 오류·중단 | 레드 |

**가공은 셋뿐이다** — base64 이미지 치환, 16k 길이 상한, 비밀키 패턴 마스킹.
텍스트 내용은 원문 그대로다. 서버가 만든 진행 보고는 `tool_result` 가 아니라 별도
`milestone` 채널로 흐른다.

칩을 눌러 채널을 걸러 볼 수 있고, 위로 스크롤하면 자동 스크롤이 멈춘다 —
심사 중 한 줄을 붙잡고 읽을 수 있다.

## OpenAI 기술과 채택 이유

| 기술 | 이유 |
|---|---|
| **Agents SDK 런타임 루프** | 도구 호출 결정을 모델에 위임하면서 스트리밍 이벤트를 그대로 중계할 수 있다. 세컨드 화면 요건이 SDK 의 이벤트 모델과 정확히 맞는다 |
| **hosted `web_search`** | 브랜드·모델이 인쇄된 상품에서만 조건부로 발화한다. 이 분기가 "입력마다 도구 호출의 개수·순서가 달라진다"의 실증 |
| **`gpt-image-2` (`images.edit`)** | 산출물 품질의 절반이 이미지다. 참조 사진 기반 편집으로 상품 정체를 보존하면서 연출만 바꾼다 |
| **구조화 출력 (JSON Schema strict)** | 등록 페이로드는 필드 하나만 틀려도 거부된다. 자유 텍스트 파싱을 쓸 수 없다 |
| **Realtime API — `gpt-realtime-2.1` 음성 서기** | 폰 링크 중 판매자의 발화를 텍스트 출력 전용 세션이 직접 이해해, 잡담을 거르고 정정을 반영한 판매 메모로 다시 쓴다. 스피커로 대답하지 않는다(`output_modalities: ["text"]`) — **첫 입력을 만드는 단계**의 보조라 자율성 계약(첫 입력 이후 개입 0회)과 충돌하지 않는다. 미개방 조직에선 전사 세션 + 텍스트 모델 2홉으로 자동 폴백 |

## 정직성 표시 수칙

한 번이라도 화면이 사실과 다른 말을 하면 그 뒤의 모든 주장이 의심받는다.

| 상황 | 화면에 쓰는 말 |
|---|---|
| 카테고리 검증 루프 미통과 | "카테고리 후보 선정 — 검증 미통과" |
| 시세 표본 0건 | "에이전트 추정 — 사진·상품 정보 근거" (**"시세 기반" 금지**) |
| 태그 사전 대조 미완 | "태그 정규화 적용 — 공식 사전 대조 미완" |
| 고시 유형 미확인 | "고시 유형 미확인 — 기타 재화로 등록" |
| 실전송 못 함 | "등록안 완성 — 스토어 전송 보류" |
| 웹 검색 안 함 | 단계 스트립에 "생략" 마이크로라벨 (대기와 구분) |

**등록필 도장은 실제로 스토어에 올라갔을 때만 찍는다.**

## 시연 전 체크리스트

- [ ] `.env.local` 에 `OPENAI_API_KEY` 와 커머스 자격증명이 있다
- [ ] 셸 프로필에 낡은 `OPENAI_API_KEY` export 가 없다
- [ ] `COMMERCE_PROXY_URL` 이 등록된 고정 IP 를 가리킨다
- [ ] `config/smartstore.local.json` 의 A/S 전화번호가 실번호다
- [ ] `origin.mode` 가 `fixed` 다 (지연 −1~2초 + 실패 경로 제거)
- [ ] `media.quality` 를 확인했다 — 기본값은 **`low` + 대표만 `medium`**(속도 우선,
      `high` 는 샷당 1분+). 시간이 더 모자라면 `galleryCount` · `detailPanelCount` 를 줄인다
- [ ] **카테고리 트리 캐시가 워밍돼 있다** (한 번 돌려 둔다 — 첫 런이 유난히 느려진다)
- [ ] 시연 브라우저가 이 origin 의 **팝업을 허용**한다
- [ ] 두 번째 화면에 `/stream` 이 **등록 시작 전에** 열려 있다
- [ ] **폰 링크 리허설을 마쳤다** — 폰에서 인증서 경고를 미리 통과했고, 카메라·마이크 권한을
      허용했고, 폰과 맥이 같은 네트워크에 있다 (막히면 폰 핫스팟)
- [ ] **맥 브라우저에 카메라 권한을 미리 허용했다** — 폰 아이가 랜딩에서 바로 켜진다.
      심사 중에 권한 팝업이 뜨면 안 된다. 거부돼 있어도 버튼 경로는 살아 있다

무대 수칙: 7분 안에 `resolve` / `retry` 를 **절대 클릭하지 않는다**(자율성 게이트).
`?preview=` 리허설 드라이버도 **심사 중 사용하지 않는다**.
