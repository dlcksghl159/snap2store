# Snap2Store — 찍으면, 등록까지

**팔 물건을 사진 찍어 올리면, 자율 에이전트가 네이버 스마트스토어 등록을 끝까지 수행한다.**
사람은 첫 입력 이후 아무것도 하지 않는다.

> 실제 등록된 상품 URL: _(첫 실등록 후 여기에 붙인다 — 아직 실행하지 않았다면 비워 둔다.
> 이 줄에 만들어 낸 링크를 넣지 않는다.)_

---

## 왜 어려운 일인가

스마트스토어 상품 하나를 살리려면 이 열 칸이 전부 채워져야 한다.

```
대표 이미지 · 추가 컷 · 상품명 · 카테고리 · 판매가
상세페이지 · 검색 태그 · 원산지 · KC 인증 · 상품정보제공고시
```

각 칸은 서로 의존한다. 카테고리가 정해져야 고시 유형과 KC 대상 여부가 나오고, 상품 정체가
확정돼야 카테고리를 찾을 수 있고, 시장 어휘를 알아야 검색되는 상품명을 쓸 수 있다.
개인 판매자는 이 의존 그래프 때문에 등록을 포기한다. 그 그래프를 사람 대신 밟는 것이 이
에이전트의 일이다.

## 포지셔닝 — 얇은 에이전트 루프 + 두꺼운 실도구

도구 호출의 결정(순서·횟수·생략)은 매 입력마다 모델이 한다. 실행은 검증된 실재료
파이프라인(실제 커머스 API, 실제 카탈로그 투표, 실제 등록 POST)이 한다.
실행이 끝나면 **진짜 상품 번호와 진짜 스토어 URL**이 나온다.

## 실행

```bash
npm install
cp .env.example .env.local          # 키를 채운다
cp config/smartstore.example.json config/smartstore.local.json
npm run dev:full                    # API :8788 + UI :5173
```

| 화면 | 주소 |
|---|---|
| 제품 화면 | http://localhost:5173 |
| 세컨드 화면 (raw API 스트림) | http://localhost:5173/stream |

### 환경변수 (`.env.local`)

| 키 | 필수 | 용도 |
|---|---|---|
| `OPENAI_API_KEY` | ✅ | 에이전트 루프 · 구조화 JSON · 이미지 생성 |
| `OPENAI_MODEL` | | 기본 `gpt-5.6-luna`. 지연이 전부다 — 같은 세대에서 더 빠른 변종이 있으면 교체 |
| `OPENAI_IMAGE_MODEL` | | 기본 `gpt-image-2` |
| `NAVER_COMMERCE_CLIENT_ID` / `_SECRET` | ✅(실등록) | 카테고리·고시·KC·원산지·태그·카탈로그·등록 |
| `COMMERCE_PROXY_URL` | ✅(실등록) | 커머스 API IP 화이트리스트 대응 고정 IP 프록시 |
| `NAVER_SEARCHAD_*` | | 상품명·태그 검색 수요 검증 (선택) |
| `SMARTSTORE_MODE` | | 기본 `live`. `dry-run` 은 사람이 고르는 모드가 아니라 시스템이 스스로 내려앉는 바닥 |

> ⚠ `.env.local` 이 진실의 원천이다. 셸 프로필에 낡은 `OPENAI_API_KEY` 가 export 돼 있으면
> `echo $OPENAI_API_KEY` 로 확인해 지운다 — 파일 값이 조용히 지는 사고가 난다.

## 아키텍처

```
사진 업로드 (POST /api/listings)
    │
    ├──────────────► 이미지 스위트 프리워밍 (즉시 시작, 에이전트와 완전히 겹침)
    │                 gpt-image-2 · 대표 1 + 갤러리 N · 하드 예산 70s
    │                 (거부 판정이 나면 AbortSignal 로 즉시 취소된다)
    │
    └──► 에이전트 루프 (Agents SDK, 스트리밍)
           │  도구 호출의 개수·순서·생략을 모델이 결정한다
           │  ├ resolve_category      (카탈로그 투표 → leaf 매핑 → LLM 검증 루프)
           │  ├ research_market_price (comps 분포 or 에이전트 추정)
           │  ├ generate_image_suite  (논블로킹 진행 스냅샷)
           │  └ web_search (hosted)   (브랜드 인쇄·주장 시 의무 1회)
           │
           └──► 구조화 draft (zod 검증)
                  │
                  ├─ [거부 게이트] riskLevel === "high" → 즉시 종착 (재료 생산 앞)
                  │
                  └──► 오케스트레이터: 재료 병렬 생산
                         ├ 카테고리 (도구 결과 재사용, 없으면 서버 폴백)
                         ├ ┌ 상품명 SEO → 태그 포트폴리오 (순서 의존 체인)
                         │ ├ 고시 · KC · 원산지 · 가격 · 상품속성
                         │ └ 상세 기획 → 세로 패널 생성
                         │   (위 세 갈래가 Promise.all 로 동시)
                         │
                         └──► 검증 · 폴백 해소 → 이미지 업로드 → 상세 HTML 조립
                                → 프리플라이트 → 등록 POST (무재시도)
```

**병렬화가 지연 예산의 전부다.** 직렬로 짜면 어떤 최적화도 90초를 못 맞춘다.

## 자율성 계약

첫 입력 이후 사람의 버튼·추가입력·수동실행이 **0회**로 종착지에 도달한다.
게이트 위반은 사람에게 넘기지 않고 폴백으로 자가 해소한다.

### 폴백 4종

| # | 게이트 위반 | 자가 해소 |
|---|---|---|
| 1 | 상품명이 등록 게이트를 어김 | `repairTitle` 로 자동 보정 → 재게이트. 재통과 실패해도 경고만 남기고 진행 |
| 2 | 카테고리 검증 루프 미통과 | 득표 1위 후보 자동 채택 + "미검증" 라벨 |
| 3 | 원산지 미판독 | 판매자 설정 기본값으로 진행 (허위가 아니라 설정 사실) |
| 4 | 시세·추정 모두 부재 | 설정 최저 안전가로 진행 + "검토 권장" 라벨 |

### 자동 강등

실등록이 물리적으로 불가능한 사유(카테고리 미확정, 프리플라이트 실패, 이미지 업로드 실패)는
**쓰기만 강등**하고 등록안은 끝까지 완성해 보고한다. 화면은 모드가 아니라 결과를 말한다 —
"등록안 완성 — 스토어 전송 보류".

### 유일한 중단

**고위험 거부 판정 하나**다. `riskLevel: "high"` 는 입력 대기가 아니라 판단이 담긴 최종
산출물이며, 재료·이미지 생산 **앞**에서 실행된다.

## 세컨드 화면 — `/stream`

`tool_call` **과** `tool_result` 가 가공 없이 실시간으로 흐른다. 빌드 파이프라인에 넣지
않고 Express 가 문자열 상수로 직접 응답하므로, 프론트 빌드가 깨져도 살아 있다.

| 채널 | 무엇이 흐르나 | 색 |
|---|---|---|
| `tool_call` | SDK 가 방출한 도구 호출 원본만 | 앰버 |
| `tool_result` | SDK 가 방출한 도구 결과 원본만 | 그린 |
| `openai_raw` | 모델 raw 스트림 이벤트 전량 | 블루 |
| `image` | 이미지 샷 시작/완료 | 마젠타 |
| `milestone` | **서버 파이프라인 진행 보고** (도구 결과가 아님) | 시안 |
| `status` | 스테이지 전환 | 회색 |
| `error` | 오류·중단 | 레드 |

**가공은 셋뿐이다** — base64 이미지 치환, 16k 길이 상한, 비밀키 패턴 마스킹.
텍스트 내용은 원문 그대로다. 서버가 만든 진행 보고는 `tool_result` 가 아니라 별도
`milestone` 채널로 흐른다.

칩을 눌러 채널을 걸러 볼 수 있고, 위로 스크롤하면 자동 스크롤이 멈춘다 —
심사 중 한 줄을 붙잡고 읽을 수 있다.

## OpenAI 기술과 채택 이유

| 기술 | 이유 |
|---|---|
| **Agents SDK 런타임 루프** | 도구 호출 결정을 모델에 위임하면서 스트리밍 이벤트를 그대로 중계할 수 있다. 세컨드 화면 요건이 SDK 의 이벤트 모델과 정확히 맞는다 |
| **hosted `web_search`** | 브랜드·모델이 인쇄된 상품에서만 조건부로 발화한다. 이 분기가 "입력마다 도구 호출의 개수·순서가 달라진다"의 실증 |
| **`gpt-image-2` (`images.edit`)** | 산출물 품질의 절반이 이미지다. 참조 사진 기반 편집으로 상품 정체를 보존하면서 연출만 바꾼다 |
| **구조화 출력 (JSON Schema strict)** | 등록 페이로드는 필드 하나만 틀려도 거부된다. 자유 텍스트 파싱을 쓸 수 없다 |
| **음성/실시간 인터페이스 — 미채택** | 입력이 사진이고 출력이 등록물이다. 실시간 대화가 개입할 지점이 없고, 오히려 자율성 게이트와 충돌한다 |

## 정직성 표시 수칙

한 번이라도 화면이 사실과 다른 말을 하면 그 뒤의 모든 주장이 의심받는다.

| 상황 | 화면에 쓰는 말 |
|---|---|
| 카테고리 검증 루프 미통과 | "카테고리 후보 선정 — 검증 미통과" |
| 시세 표본 0건 | "에이전트 추정 — 사진·상품 정보 근거" (**"시세 기반" 금지**) |
| 태그 사전 대조 미완 | "태그 정규화 적용 — 공식 사전 대조 미완" |
| 고시 유형 미확인 | "고시 유형 미확인 — 기타 재화로 등록" |
| 실전송 못 함 | "등록안 완성 — 스토어 전송 보류" |
| 웹 검색 안 함 | 단계 스트립에 "생략" 마이크로라벨 (대기와 구분) |

**등록필 도장은 실제로 스토어에 올라갔을 때만 찍는다.**

## 시연 전 체크리스트

- [ ] `.env.local` 에 `OPENAI_API_KEY` 와 커머스 자격증명이 있다
- [ ] 셸 프로필에 낡은 `OPENAI_API_KEY` export 가 없다
- [ ] `COMMERCE_PROXY_URL` 이 등록된 고정 IP 를 가리킨다
- [ ] `config/smartstore.local.json` 의 A/S 전화번호가 실번호다
- [ ] `origin.mode` 가 `fixed` 다 (지연 −1~2초 + 실패 경로 제거)
- [ ] **카테고리 트리 캐시가 워밍돼 있다** (한 번 돌려 둔다 — 첫 런이 유난히 느려진다)
- [ ] 시연 브라우저가 이 origin 의 **팝업을 허용**한다
- [ ] 두 번째 화면에 `/stream` 이 **등록 시작 전에** 열려 있다

무대 수칙: 7분 안에 `resolve` / `retry` 를 **절대 클릭하지 않는다**(자율성 게이트).
`?preview=` 리허설 드라이버도 **심사 중 사용하지 않는다**.
